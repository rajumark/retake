Why Retake

Catch the bad photo before it's sent

No server, no API key, no per-photo bill. A small Kotlin library that you can read, test and ship.

Six problems, one call

Blur, too dark, too bright, glare, noise and a finger over the lens. A score from 0 to 1 for each, the verdict, and a short hint to show the user.

Knows a screenshot

Screenshots, chats, documents and graphics aren't camera photos, so they count as good. On a real phone it flagged 4% of the Screenshots folder, and none of 102 app screenshots in the tests.

No dependencies

Pure Kotlin inference. There is no ONNX Runtime, TFLite, ML Kit or native code, and it runs on Android (minSdk 21), iOS, macOS, JVM desktop, JavaScript and WebAssembly, from Kotlin or Java.

Private & offline

The model ships inside the library on every platform. Photos never leave the device: no network calls, no permissions, no telemetry.

Install

Add it to your build

One line in your Gradle file, from Maven Central. Works in commonMain for Android, iOS, macOS, JVM desktop, JavaScript and WebAssembly. No API key, no account.

Maven Central live
// build.gradle.kts: commonMain, or any platform source set
dependencies {
    implementation("io.github.rajumark:retake:1.0.0")
}

// Gradle picks the right artifact per platform:
// retake-android · retake-jvm · retake-iosarm64 · retake-iossimulatorarm64
// retake-macosarm64 · retake-js · retake-wasm-js
Build with a prompt
Add Retake from rajumark to this Kotlin Multiplatform or Android project.

What it does: on-device photo quality check. Given a photo's pixels, it says whether the photo is good or should be retaken, with a 0..1 score for blur, dark, bright (over-exposed), glare, noise and finger (over the lens), plus a short hint per problem. Screenshots and graphics count as good. 0.5 MB, no dependencies, no network.

Install (Maven Central, no extra repository):
  build.gradle.kts (commonMain or any source set): implementation("io.github.rajumark:retake:1.0.0")
  Platforms: Android, iOS, macOS, JVM desktop, JavaScript, WebAssembly

Usage:
  val retake = Retake()                              // off the main thread, keep one instance
  val check = retake.check(argb, width, height)      // ARGB pixels; Android: retake.check(bitmap) or check(context, uri)
  if (!check.isGood) show(check.issues.first().hint) // e.g. "Blurry: hold still and tap to focus"

Repo: https://github.com/rajumark/retake#readme
Add the dependency, then follow the README for the exact API and current version.
Usage

One call per photo

Load once and reuse the instance. check() is thread-safe; run it on a background thread after a photo is taken or picked.

Kotlin
val retake = Retake()

val check = retake.check(argb, width, height)
// PhotoCheck(retake: BLUR, blur=0.991, dark=0.012, ...)
check.isGood               // false
check.issues               // [BLUR]
check.issues.first().hint  // "Blurry: hold still and tap to focus"

// Android shortcuts
retake.check(bitmap)
retake.check(context, uri) // reduced-size decode + EXIF rotation
Java
try (Retake retake = new Retake()) {
    PhotoCheck check = retake.check(argb, width, height);
    if (!check.isGood()) {
        String hint = check.getIssues().get(0).getHint();
    }
}

Size0.5 MB—~350 MB

The OpenCV rules and CLIP had their lines tuned on the validation set, to be fair to them. The rules can't detect a finger, and still flag about half of all good photos; CLIP flags almost every photo for something. In the pure-Kotlin library a 1040 × 780 photo takes about 90 ms on a laptop JVM and about 235 ms in a browser; an 800 px photo takes 110–150 ms in the Android sample on an emulator. Weak spots: real glare is caught less often than the other problems, and very dark night photos or deliberate motion blur can be flagged (raise the threshold to be lenient).

FAQ

Questions

What is Retake?

A Kotlin Multiplatform library (Android, iOS, macOS, JVM desktop, JavaScript, WebAssembly) that checks a photo on the device and says whether it's good or should be retaken, and why.

Which problems does it find?

Blur (out of focus, motion, hand shake), too dark, too bright (blown out), glare and reflections, heavy noise, and a finger or object covering part of the lens. Each gets a score from 0 to 1; 0.5 is the default line.

What about screenshots and graphics?

They count as good: a dark-mode screen isn't an under-exposed photo. Retake was trained with generated screenshots, chats, documents and posters for exactly this, and flags none of 102 real app screenshots.

How fast is it?

About 90 ms per photo on a laptop JVM, 110–150 ms in the Android sample on an emulator and about 235 ms in a browser, including the shrink to 1024 px. It's meant for checking a photo after it's taken, on a background thread. On Android, check(context, uri) decodes big photos at reduced size, which saves most of the decode time.

Is the Kotlin port exact?

The tests compare it with the reference (OpenCV preprocessing + the same int8 weights in PyTorch) on 13 images on every target: the same 4 detail crops, and every score within 0.00023.

How much does Retake cost?

Nothing for products with up to 10,000 monthly active devices per platform, including commercial apps. There is no API key or account, and no limit on how often it runs. Above that, a commercial license is needed; see Pricing.
